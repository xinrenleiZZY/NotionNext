## 一、世界观 · 起源故事

## 二、架构解析 · 空间站四层结构

### 2.1 四层模型总览

```
┌─────────────────────────────────────────────────────────┐
│  Layer 4: 🌌 未知内核区  (UNKNOWN CORE)                 │
│           → 钟元留下的核心算法，尚未完全解析               │
├─────────────────────────────────────────────────────────┤
│  Layer 3: 🚪 裂隙端点层  (RIFT ENDPOINTS)               │
│           → 对外接口（GitHub / IPFS / Notion 同步）      │
├─────────────────────────────────────────────────────────┤
│  Layer 2: 💫 数据流星走廊  (DATA CORRIDOR)              │
│           → 消息队列 · 知识检索 · 道友评论流转           │
├─────────────────────────────────────────────────────────┤
│  Layer 1: 📚 知识锚点层  (KNOWLEDGE ANCHORS)            │
│           → 核心存储 · 技术文档 · 知识图谱 · 修炼记录    │
└─────────────────────────────────────────────────────────┘
```

### 2.2 Layer 1 · 知识锚点层（核心存储）

这是空间站的「地基」，存放所有结构化知识。以 **Markdown + YAML Front Matter** 为统一格式，便于版本管理。

**一个锚点文件的标准结构：**

```markdown
---
anchor_id: "ANC-2026-00088"
title: "Docker Compose 健康检查最佳实践"
type: "technique"          # technique | essay | exploration | resource
domain: ["Docker", "DevOps"]
level: 3                   # 1:入门 2:进阶 3:高阶 4:内核级
author: "xinrenleiZZY"
created_at: 2026-08-01
updated_at: 2026-08-22
references:
  - "ANC-2026-00012"
  - "https://docs.docker.com/compose/compose-file/05-services/#healthcheck"
quality: 4.6               # 道友评分（1-5星）
tags: ["Docker Compose", "运维", "健康检查"]
pin: false
---

# Docker Compose 健康检查最佳实践

（正文内容 ...）
```

**锚点类型定义：**

| type | 中文 | 说明 |
|------|------|------|
| `technique` | 技术锚点 | 教程、技巧、踩坑、最佳实践（占比最高 ~60%）|
| `essay` | 随笔锚点 | 修仙感悟、年度复盘、行业观察（~15%）|
| `exploration` | 探索日志 | 道友提交的第一手探索记录（~20%）|
| `resource` | 资源锚点 | 工具清单、书单、模型榜单（~5%）|

### 2.3 Layer 2 · 数据流星走廊

> 「数据在空间站内不是静止的，是以流星形态流动的。」

走廊的实现很简单，就是一个**事件驱动 + 检索系统**：

```
道友新建探索日志
    ↓
[事件总线（GitHub Issues Webhook）]
    ↓ 自动索引
[全文检索引擎（本地 Whoosh / 或接入 Algolia）]
    ↓ 自动关联
[知识图谱：根据 tags / references 构建边]
    ↓
首页更新 · 道友邮件通知 · 锚点数 +1
```

### 2.4 Layer 3 · 裂隙端点（对外接口）

目前开放了**一个**裂隙端点（GitHub），未来会扩展多个：

| 裂隙 | 状态 | 协议 | 说明 |
|-----|------|------|-----|
| 🐙 GitHub（xinrenleiZZY/Juxing-Space-Station）| ✅ 开放 | Git / HTTPS | 主入口，PR=探索申请 |
| 📝 Notion 同步 | 🚧 内测中 | API | 锚点文件 ↔ Notion 页面双向同步 |
| 🪐 IPFS 只读镜像 | 📋 规划中 | IPFS | 抗审查、永久化存证 |
| 💬 飞书群接入 | 📋 规划中 | Webhook | 群里发消息直接创建探索草稿 |

### 2.5 Layer 4 · 未知内核区（钟元遗产）

目前已解析出的线索：
1. 内核入口是一个 **RSA 4096 公钥加密的 zip 包**
2. 内部推测是「知识图谱自动生成算法 + 推荐引擎」
3. 钟元留下的解锁提示是一句古诗：「**欲寻内核处，先点千星灯**」—— 推测仓库到 1000 Star 时会触发自动解密

> 💡 **道友挑战：** 等聚星空间站 GitHub 到 1000 Star，我们一起看看钟元到底埋了什么宝贝！⭐

## 三、道友加入指南（如何提交你的探索）

### 方式 A · Pull Request 提探索日志（推荐新手）

```bash
# 1. Fork 仓库
浏览器打开：https://github.com/xinrenleiZZY/Juxing-Space-Station → Fork

# 2. 克隆到本地
git clone https://github.com/<你的ID>/Juxing-Space-Station.git
cd Juxing-Space-Station

# 3. 新建你的探索锚点文件
mkdir -p anchors/explorations/2026/09
cat > anchors/explorations/2026/09/<你的道号>-<主题>.md <<EOF
---
anchor_id: "ANC-2026-$(date +%j)-$(head -c 4 /dev/urandom | xxd -p)"
title: "【探索】XXX 主题的 XXX 发现"
type: "exploration"
domain: ["Docker", "Python", "你的技术域"]
level: 2
author: "你的道号"
created_at: $(date +%F)
references: []
quality: 0.0
tags: ["探索日志", "XXX"]
pin: false
---

# 我的探索

## 背景
（写一下你探索的是什么问题）

## 过程
（你具体做了什么，代码 / 命令 / 截图）

## 结果
（发现了什么，解决了什么问题）

## 感悟
（一句话总结）
EOF

# 4. 提交 PR
git checkout -b feat/exploration-<你的道号>
git add .
git commit -m "feat(exploration): 道号<XXX>的探索日志 · 主题：XXX"
git push origin feat/exploration-<你的道号>
# 然后回到 GitHub 网页点「Compare & Pull Request」
```

### 方式 B · 直接开 Issue（不想写代码的道友）

直接到 [Issues 区](https://github.com/xinrenleiZZY/Juxing-Space-Station/issues/new/choose)，按模板填：

- 📌 **建议型**：「我觉得空间站可以加个 XX 功能」
- 📚 **分享型**：「我最近学到 XX，放这给大家参考」
- ❓ **提问型**：「某个锚点我看不懂，有人能讲解吗？」
- 🐛 **Bug 型**：「锚点 ANC-2026-00045 链接失效」

### 方式 C · 邀请成为「空间站维护者」

如果你一年贡献 12 篇以上高质量探索日志，你会被邀请为 **Collaborator**：
- 直接拥有写权限，不用走 Fork
- 参与「内核区探索小组」
- 新探索优先进入首页「道友风采」

## 六、空间站 · 行为准则（仙庭公约）

> 「聚星空间站不是一个项目，它是一个世界。**对待世界的方式，决定了你自己的高度。**」

### ✅ 我们欢迎的

1. **真诚分享**：哪怕是一句「我踩过这个坑」，也比沉默好
2. **认真提问**：提问前先搜 → 搜不到再问 → 附上你的环境和尝试
3. **互相尊重**：技术观点可以争论，对人保持礼貌
4. **文档完善**：你的探索日志就是后来者的路

### ❌ 我们禁止的

1. 广告 / 推广 / 引流无关的内容
2. 直接复制别人的文章不注明出处
3. 攻击性言论、地域歧视、人身攻击
4. 提交「测试 PR」占用维护者时间（真的想试手请去自己的仓库）
