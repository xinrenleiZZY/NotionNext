# 永恒仙庭的宝藏：那些值得收藏的技术资源

> 收藏夹里的链接 90% 不会再打开。这份清单只留「真的用过、并且还在用」的。

## 一、学习路线：先建立地图

| 资源 | 用途 |
| --- | --- |
| [roadmap.sh](https://roadmap.sh) | 各方向技能树，用来查缺补漏 |
| MDN Web Docs | 前端权威文档，比搜索引擎可靠 |
| Python 官方文档 | 标准库与语言特性，别只看教程 |
| PostgreSQL 官方文档 | SQL 与运维细节，写得极好 |

## 二、工具：少而精

**开发**
- VS Code：插件只留必要项，其余全关
- Docker Desktop / WSL2：本地环境一致性
- Postman / Hoppscotch：接口调试

**运维**
- Nginx：反向代理与网关
- Uptime Kuma：服务可用性监控（自建，轻量）
- Portainer：可视化管理 Docker（可选）

**效率**
- Everything（Windows）：秒搜文件
- DBeaver / pgAdmin：数据库管理
- Obsidian：本地知识库，与 Wiki 互补

## 三、文档与规范

- 《Google 工程实践文档》：代码评审、测试标准
- 《12 Factor App》：服务化部署的经典
- 《阿里 Java 开发手册》：即使不写 Java，规范思路可迁移
- OWASP Top 10：安全入门必读

## 四、社区与信息源

| 来源 | 用途 |
| --- | --- |
| GitHub Trending | 看趋势，不盲从 |
| Hacker News | 技术讨论与英文一手信息 |
| 少数派 / 即刻 | 中文工具与效率向 |
| 各项目 Release Notes | 比博客更准的「新特性」来源 |

## 五、我的使用原则

1. **每个方向只留 1–2 个入口**，避免选择困难
2. **工具能用命令行就别装 GUI**，脚本可复现
3. **文档优先于教程**：教程会过时，官方文档不会
4. **收藏 = 已读**：没读完的不收藏，先丢到待读清单

## 结语

资源的价值不在数量，而在**你能不能在下一次遇到问题时想起它**。把这份清单压缩到 20 条以内，才是真的「宝藏」。
