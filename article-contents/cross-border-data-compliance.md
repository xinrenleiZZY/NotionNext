# 跨境数据合规：电商数据采集的法律边界

> 能爬 ≠ 能存 ≠ 能用。跨境场景下，这三件事的边界各不相同。

做跨境电商的人几乎都会采集数据：竞品价格、评论、销量。但「技术上做到」和「法律上允许」是两件事。这篇从工程视角梳理边界。

## 一、四条最容易踩的红线

### 1. 个人信息

商品价格是公开信息，**但评论者昵称、头像、地址、订单属于个人信息**。

- 只采商品维度（标题、价格、评分、库存），不采用户维度
- 必须采时做脱敏（哈希/匿名化），并限定时长
- 中欧都适用「最小必要」原则

### 2. robots 与用户协议

robots.txt 不是法律，但是**判断「是否违背权利人意愿」的重要证据**。用户协议里明确禁止抓取的，风险显著上升。

工程上的做法：采集前把目标站点的 robots 与条款纳入配置，命中的域名走白名单审批。

### 3. 跨境传输

中国《数据出境安全评估办法》、欧盟 GDPR 都对跨境传输有要求。

- 数据存在境内服务器 vs 直接落到海外，合规路径不同
- 涉及个人信息出境，可能需要安全评估或标准合同
- 建议：**先落境内，再做脱敏后的跨境分析**

### 4. 不正当竞争

大批量、高频、替代性采集（把对方数据直接做成同类产品）风险最高。判例中常见考量：采集规模、频率、是否影响对方正常运营、是否实质性替代。

## 二、工程侧合规清单

| 环节 | 检查项 |
| --- | --- |
| 采集前 | 目标站点是否公开？robots 是否允许？协议是否禁止？ |
| 采集中 | 是否只采公开字段？频率是否克制？是否伪装成正常用户访问？ |
| 存储 | 是否脱敏？是否加密？保留期限是否明确？ |
| 使用 | 是否超范围使用？是否对外提供？是否用于训练？ |
| 跨境 | 是否出境？是否评估？是否签标准合同？ |

## 三、技术上的「合规默认值」

把合规做成默认行为，比事后审查更可靠：

```python
SENSITIVE_FIELDS = {"nickname", "avatar", "user_id", "address", "phone"}

def sanitize(record: dict) -> dict:
    return {k: v for k, v in record.items() if k not in SENSITIVE_FIELDS}
```

- 采集层直接丢弃敏感字段（而不是存下来再删）
- 日志不打完整响应体，只打状态码与耗时
- 数据保留期写进配置，到期自动清理

## 四、我的三条实践原则

1. **公开数据 ≠ 可任意使用**：采集范围要与业务必要性匹配
2. **能不用个人信息就不用**：从源头减少合规负担
3. **留证据**：采集策略、审批记录、脱敏日志，都是将来「证明自己合规」的材料

## 五、什么时候必须找专业意见

- 数据涉及个人信息且要出境
- 采集规模大、频率高、涉及竞争关系
- 数据用于训练模型或对外交易
- 对方已发出警告或律师函

这几种情况，提前咨询的成本远低于事后处理。

## 结语

合规不是「限制业务」，而是**让业务能长期做下去**。把边界搞清楚，采集系统才敢规模化。
